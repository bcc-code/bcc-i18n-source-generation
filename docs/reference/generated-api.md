# Reference: generated API

The generator emits these types into the namespace set by [`GeneratedNamespace`](msbuild.md#properties):

| Type | File | Visibility | Generated when |
| --- | --- | --- | --- |
| `Language` | `Language.g.cs` | `public static class` | The fallback file exists |
| `LocalizedLanguage` | `LocalizedLanguage.g.cs` | `public readonly struct` | The fallback file exists |
| `LocalizedLanguageGroups` | `LocalizedLanguageGroups.g.cs` | `public static class`, hidden from completion | The fallback file exists |
| `LanguageKeys` | `LanguageKeys.g.cs` | `public static class` | The fallback file exists |
| `LanguageStrings` | `LanguageStrings.g.cs` | `public static class` | The fallback file exists |
| `LanguageTranslations` | `LanguageTranslations.g.cs` | `internal static class` | The fallback file exists |
| `LanguageStringLocalizer` | `LanguageStringLocalizer.g.cs` | `public sealed class` | The fallback file exists and the project references `Microsoft.Extensions.Localization.Abstractions` |
| `LanguageStringLocalizerFactory` | `LanguageStringLocalizerFactory.g.cs` | `public sealed class` | Same as `LanguageStringLocalizer` |

If the fallback language file is missing, nothing is generated and [I18N004](diagnostics.md#i18n004) is reported.

All generated types have `[GeneratedCode("BccCode.I18N.SourceGen", "<version>")]`. Each file starts with `// <auto-generated/>` and `#nullable enable`.

The examples on this page use this fallback file (`en.json`):

```json
{
  "greeting": "Hello, {name}!",
  "menu": { "save": "Save" },
  "files": "no files | one file | {count} files"
}
```

## Names

Key structure and member names come from the **fallback file**. Keys that exist only in other languages are not part of `Language`, `LocalizedLanguage` or `LanguageKeys` ([I18N008](diagnostics.md#i18n008)).

- A JSON object becomes a nested group. A string becomes a member.
- A dot in a JSON property name is a path separator: `{ "a.b": "x" }` is the same key as `{ "a": { "b": "x" } }`.
- Names are made into valid C# identifiers:
  - A character that is not valid in an identifier becomes `_` (`my-key` → `my_key`).
  - A name that does not start with a letter or `_` gets a `_` prefix (`1st` → `_1st`).
  - A C# keyword gets an `@` prefix (`class` → `@class`).
- Members are emitted in ordinal order of their names.
- Each member has an XML doc comment with the fallback text, after linked messages are resolved.

## Member shapes

How a key becomes a member, in `Language`, `LocalizedLanguage` and its groups:

| Fallback text | Member |
| --- | --- |
| No placeholders, not plural | Property: `string save` |
| Placeholders `{a}`, `{b}` | Method: `string greeting(object a, object b)` |
| Plural (any language uses `\|`) | Method with `int` first parameter: `string files(int count)` |

Parameter rules:

- Parameters follow the order in which placeholders first appear in the fallback text. A placeholder used several times is one parameter.
- Placeholder parameters are `object`. The count parameter of a plural key is `int`.
- For a plural key, the first placeholder in the fallback text is the count. If the fallback text has no placeholder, the count is named `count`.
- If the fallback text is not plural but another language is, the first parameter is `int count`, followed by the fallback text's other placeholders. Use `{count}` in the plural language.
- List placeholders `{0}`, `{1}` become parameters `_0`, `_1`.
- Placeholder names that sanitize to the same identifier get a numeric suffix (`_1st`, `_1st2`).

See [Message syntax](message-syntax.md) for placeholders, plural forms, links and literals.

## `Language`

```csharp
public static class Language
{
    public static string greeting(object name) => ...;
    public static string files(int count) => ...;
    public static class menu
    {
        public static string save => ...;
    }
}
```

- Each group is a nested `public static class`.
- The language is chosen from `CultureInfo.CurrentUICulture` with `LanguageStrings.ResolveLanguage` on every call.
- Placeholder values are formatted with `CultureInfo.CurrentCulture`.
- If the chosen language does not have the key, or its text uses placeholders the fallback text does not have ([I18N006](diagnostics.md#i18n006)), the fallback text is used.

## `LocalizedLanguage`

```csharp
public readonly struct LocalizedLanguage
{
    public LocalizedLanguage(CultureInfo culture);
    public string greeting(object name) => ...;
    public string files(int count) => ...;
    public LocalizedLanguageGroups.menu menu => ...;
}
```

- Same members as `Language`, as instance members.
- The constructor resolves the language once with `LanguageStrings.ResolveLanguage(culture)` and stores the culture.
- Placeholder values are formatted with the stored culture.
- `default(LocalizedLanguage)` uses the fallback language and `CultureInfo.InvariantCulture`.
- A member cannot have the name of its enclosing type. A root key named `LocalizedLanguage` becomes the member `LocalizedLanguage_` (with a number added if that name is taken). The same applies in group structs.

## `LocalizedLanguageGroups`

Contains one `public readonly struct` per group, returned by the group properties of `LocalizedLanguage`. Struct names are derived from the key path (`menu`, `menu_sub`) and get a numeric suffix on a collision. The class has `[EditorBrowsable(EditorBrowsableState.Never)]`. The struct constructors are `internal`. Refer to these types only through `var` or the property that returns them.

## `LanguageKeys`

```csharp
public static class LanguageKeys
{
    public const string greeting = "greeting";
    public const string files = "files";
    public static class menu
    {
        public const string save = "menu.save";
    }
}
```

Each key is a `const string` holding the dot-separated key path. `LanguageKeys` depends only on the fallback file, so edits to other language files do not change it.

## `LanguageStrings`

Run-time lookups by key path. Values are the stored texts with linked messages resolved. Literals such as `{'@'}` and format specifiers such as `{date:d}` are kept as written.

### Lookup

| Member | Description |
| --- | --- |
| `string GetString(string key)` | Text for `key` in the language of `CultureInfo.CurrentUICulture`, else in the fallback language, else `key`. |
| `string GetString(string key, CultureInfo culture)` | Same, with the language matched from `culture`. |
| `string? GetStringOrNull(string key)` | Like `GetString`, but returns `null` when neither the matched language nor the fallback language has the key. |
| `string? GetStringOrNull(string key, CultureInfo culture)` | Same, with the language matched from `culture`. |
| `string ResolveLanguage(CultureInfo culture)` | The translation file language for `culture`. See [Culture matching](../explanation/culture-matching-and-fallback.md). |

Keys are compared case-sensitively. Keys that exist only in a non-fallback language ([I18N008](diagnostics.md#i18n008)) are found for that language.

### Listings

| Member | Description |
| --- | --- |
| `string FallbackLanguage { get; }` | The fallback language, lowercased. |
| `IReadOnlyList<string> Languages { get; }` | All translation file languages, lowercased, in ordinal order. |
| `IReadOnlyList<string> Keys { get; }` | Key paths of the fallback file, in ordinal order. |
| `IReadOnlyList<KeyValuePair<string, string>> GetAllStrings(string language)` | All key/value pairs of a file language (case-insensitive), in ordinal key order. Empty for an unknown language. |
| `IReadOnlyList<KeyValuePair<string, string>> GetAllStrings(CultureInfo culture, bool includeFallback = true)` | The pairs of the language matched from `culture`. With `includeFallback`, pairs for fallback keys that the language lacks are appended. |

`Languages`, `Keys` and both `GetAllStrings` methods create a new array or list on every call.

### Formatting

| Member | Description |
| --- | --- |
| `string Format(string key, params object?[] args)` | Formats the stored text of `key`. Language from `CultureInfo.CurrentUICulture`, values formatted with `CultureInfo.CurrentCulture`. |
| `string Format(string key, CultureInfo culture, params object?[] args)` | Same, with language and formatting from `culture`. |

Behavior:

- Arguments are matched by position to the parameters of the `Language` member for the key.
- `{name}` and `{name:format}` are replaced with the formatted argument. `{'text'}` becomes `text`.
- A placeholder without a matching argument stays as written.
- An unknown key returns the key.
- For a plural text, the first argument is the count. Any integral or floating point type is accepted; fractions are not rounded. Without a numeric first argument the count is 1. See [Plural selection](../explanation/plural-selection.md#languagestringsformat).
- If the matched language's text has placeholders that the key does not have ([I18N006](diagnostics.md#i18n006)), the fallback text is used, as in `Language`.
- Links that could not be resolved ([I18N010](diagnostics.md#i18n010)) are kept as written.

## `LanguageStringLocalizer`

Implements `Microsoft.Extensions.Localization.IStringLocalizer`. Generated only when the compilation contains `IStringLocalizer`, `IStringLocalizerFactory` and `LocalizedString` from `Microsoft.Extensions.Localization`.

| Member | Description |
| --- | --- |
| `LanguageStringLocalizer()` | Uses `CultureInfo.CurrentUICulture` (language) and `CultureInfo.CurrentCulture` (formatting) at the time of each call. |
| `LanguageStringLocalizer(CultureInfo culture)` | Always uses `culture`. |
| `LocalizedString this[string name]` | `LanguageStrings.GetStringOrNull(name)`. If `null`: value `name`, `ResourceNotFound = true`. |
| `LocalizedString this[string name, params object[] arguments]` | The text formatted like `LanguageStrings.Format`, except that a numeric placeholder `{n}` takes `arguments[n]`. A numeric placeholder whose index is not passed stays as written. Unknown key: value `name`, `ResourceNotFound = true`. |
| `IEnumerable<LocalizedString> GetAllStrings(bool includeParentCultures)` | `LanguageStrings.GetAllStrings(culture, includeParentCultures)`. `true` adds the fallback strings that the language lacks. |
| `IStringLocalizer WithCulture(CultureInfo culture)` | Returns `new LanguageStringLocalizer(culture)`. Only generated when the referenced `IStringLocalizer` declares `WithCulture` (versions 2.x and 3.x). |

## `LanguageStringLocalizerFactory`

Implements `IStringLocalizerFactory`. Both `Create(Type)` and `Create(string baseName, string location)` return `new LanguageStringLocalizer()`, because the whole project shares one set of translation files. See [Use IStringLocalizer](../how-to/use-istringlocalizer.md) for registration.

## `LanguageTranslations`

`internal`. Holds one method per key with the translations of all languages as a `switch` expression. `Language` and `LocalizedLanguage` call it. It is not meant to be called directly.
